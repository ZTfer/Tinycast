# 音频播放功能 Spec

## 为什么

音频播放是播客应用的核心功能，用户需要能够播放、暂停、跳转、调整播放速度和音量。系统需要提供流畅的播放体验，并支持后台播放。

## 变更内容

- 集成 just_audio 和 audio_service
- 实现音频播放控制
- 实现播放状态管理
- 实现播放进度持久化
- 实现后台播放支持

## 影响

- 受影响的规格：队列管理、收藏管理
- 受影响的代码：Data 层（repositories）、Domain 层（usecases）、Presentation 层（providers、widgets）

## 新增需求

### 需求：音频播放器初始化

系统应使用 just_audio 初始化音频播放器。

#### 场景：初始化播放器

- **当**应用启动
- **则**应初始化 AudioPlayer 实例
- **并且**配置播放器参数
- **并且**处理播放器状态变化

### 需求：播放控制

系统应提供完整的播放控制功能。

#### 场景：播放节目

- **当**用户点击播放按钮
- **则**系统应加载音频 URL
- **并且**开始播放
- **并且**更新播放状态
- **并且**更新迷你播放器

#### 场景：暂停播放

- **当**用户点击暂停按钮
- **则**系统应暂停播放
- **并且**保存当前播放位置
- **并且**更新播放状态

#### 场景：跳转播放位置

- **当**用户拖动进度条
- **则**系统应跳转到指定位置
- **并且**更新播放进度显示

#### 场景：快进/快退

- **当**用户点击快进/快退按钮
- **则**系统应按设置的时间间隔跳转
- **并且**更新播放进度

### 需求：播放速度调整

系统应支持调整播放速度。

#### 场景：调整播放速度

- **当**用户选择播放速度
- **则**系统应设置播放速度（0.5x、0.75x、1x、1.25x、1.5x、2x）
- **并且**保存用户偏好
- **并且**更新播放速度显示

### 需求：音量控制

系统应支持音量控制。

#### 场景：调整音量

- **当**用户调整音量
- **则**系统应设置音量大小（0.0 - 1.0）
- **并且**保存用户偏好
- **并且**更新音量显示

### 需求：播放状态管理

系统应实时管理播放状态。

#### 场景：播放状态更新

- **当**播放状态发生变化
- **则**应通知所有监听器
- **并且**更新 UI 显示
- **并且**更新播放进度

#### 场景：播放进度更新

- **当**播放进度变化
- **则**应定期更新播放位置
- **并且**更新进度条显示
- **并且**保存播放位置到数据库

### 需求：播放位置持久化

系统应保存和恢复播放位置。

#### 场景：保存播放位置

- **当**用户暂停或退出应用
- **则**应保存当前播放位置
- **并且**保存当前播放的节目 ID
- **并且**保存到数据库

#### 场景：恢复播放位置

- **当**用户重新打开应用
- **则**应从数据库加载上次播放位置
- **并且**恢复播放状态
- **并且**更新 UI

### 需求：后台播放

系统应支持后台播放。

#### 场景：后台播放

- **当**应用进入后台
- **则**应继续播放音频
- **并且**显示媒体通知
- **并且**支持锁屏控制

#### 场景：媒体通知

- **当**播放节目时
- **则**应显示媒体通知
- **并且**显示节目信息（标题、封面）
- **并且**提供播放控制按钮

### 需求：播放完成处理

系统应处理播放完成事件。

#### 场景：播放完成

- **当**节目播放完成
- **则**应标记节目为已播放
- **并且**自动播放下一集（如果启用连续播放）
- **或者**停止播放（如果未启用连续播放）

### 需求：错误处理

系统应优雅地处理播放错误。

#### 场景：播放错误

- **当**播放失败
- **则**应显示错误提示
- **并且**提供重试选项
- **并且**记录错误日志

#### 场景：网络错误

- **当**网络中断
- **则**应暂停播放
- **并且**显示网络错误提示
- **并且**等待网络恢复

无
