# TinyCast 播客应用 MVP 规格说明

## 为什么
当前实现已经拥有完整的桌面 UI 结构，但缺乏功能性播客应用所需的核心功能、数据持久化和业务逻辑。用户需要订阅播客、播放节目、管理下载，并在不同会话中保持收听进度。

## 变更内容
- 实现完整的播客订阅和管理系统
- 添加带控制的音频播放功能
- 创建本地数据持久化层
- 实现下载管理
- 添加收藏/队列管理
- 实现搜索功能
- 添加设置持久化
- 创建全面的测试套件

## 影响
- 受影响的规格：无（新功能）
- 受影响的代码：所有 UI 组件都需要数据集成、新的服务层、数据模型和状态管理

## 新增需求

### 需求：播客订阅管理
系统应允许用户通过 RSS 订阅源和 OPML 文件订阅播客。

#### 场景：通过 RSS 订阅
- **当**用户输入有效的 RSS 订阅源 URL
- **则**系统应获取并解析播客订阅源
- **并且**将播客添加到用户的资料库
- **并且**显示成功通知

#### 场景：通过 OPML 订阅
- **当**用户导入 OPML 文件
- **则**系统应解析文件中的所有播客订阅源
- **并且**将所有有效播客添加到资料库
- **并且**显示导入摘要

#### 场景：无效的 RSS 订阅源
- **当**用户输入无效的 RSS 订阅源 URL
- **则**系统应显示适当的错误消息
- **并且**不将播客添加到资料库

### 需求：播客资料库管理
系统应显示和管理已订阅的播客。

#### 场景：查看资料库
- **当**用户导航到资料库页面
- **则**系统应显示所有已订阅的播客
- **并且**显示每个播客的最新节目
- **并且**显示自上次更新以来的时间

#### 场景：取消订阅播客
- **当**用户从播客菜单中选择取消订阅
- **则**系统应从资料库中移除播客
- **并且**删除已下载的节目（可选）
- **并且**立即更新 UI

### 需求：节目播放
系统应为播客节目提供音频播放功能。

#### 场景：播放节目
- **当**用户点击播放某个节目
- **则**系统应开始音频播放
- **并且**用节目信息更新迷你播放器
- **并且**显示播放进度

#### 场景：播放控制
- **当**用户与播放控件交互
- **则**系统应支持播放/暂停、快进/快退、跳转
- **并且**调整播放速度（0.5x、0.75x、1x、1.25x、1.5x、2x）
- **并且**调整音量

#### 场景：播放进度持久化
- **当**用户停止播放
- **则**系统应保存当前播放位置
- **并且**在恢复节目时恢复位置

### 需求：队列管理
系统应允许用户管理节目播放队列。

#### 场景：添加到队列
- **当**用户将节目添加到队列
- **则**系统应将节目添加到播放队列
- **并且**更新队列显示

#### 场景：从队列中移除
- **当**用户从队列中移除节目
- **则**系统应从队列中移除节目
- **并且**更新队列显示

#### 场景：重新排序队列
- **当**用户将节目拖动到新位置
- **则**系统应更新队列顺序
- **并且**保存新顺序

#### 场景：自动播放下一集
- **当**当前节目播放完成
- **则**系统应自动播放队列中的下一个节目（如果在设置中启用）

### 需求：下载管理
系统应允许用户下载节目以供离线收听。

#### 场景：下载节目
- **当**用户启动节目下载
- **则**系统应下载节目音频文件
- **并且**显示下载进度
- **并且**将文件存储在本地

#### 场景：自动下载
- **当**已订阅播客有新节目可用
- **则**系统应在设置中启用时自动下载
- **并且**遵守下载设置（仅 WiFi、仅收藏等）

#### 场景：移除已下载的节目
- **当**用户删除已下载的节目
- **则**系统应移除本地文件
- **并且**更新下载状态

### 需求：收藏管理
系统应允许用户将节目标记为收藏。

#### 场景：添加到收藏
- **当**用户将节目标记为收藏
- **则**系统应将节目添加到收藏列表
- **并且**更新收藏指示器

#### 场景：从收藏中移除
- **当**用户取消收藏节目
- **则**系统应从收藏列表中移除节目
- **并且**更新收藏指示器

### 需求：搜索功能
系统应提供播客和节目的搜索功能。

#### 场景：搜索播客
- **当**用户搜索播客
- **则**系统应搜索播客目录（例如 Podcast Index）
- **并且**显示匹配结果
- **并且**允许从结果中订阅

#### 场景：搜索本地资料库
- **当**用户在应用内搜索
- **则**系统应搜索已订阅的播客和节目
- **并且**显示匹配结果
- **并且**维护搜索历史

### 需求：设置管理
系统应允许用户配置应用偏好设置。

#### 场景：播放设置
- **当**用户配置播放设置
- **则**系统应保存快进/快退间隔
- **并且**保存连续播放偏好
- **并且**保存默认播放速度

#### 场景：下载设置
- **当**用户配置下载设置
- **则**系统应保存自动下载偏好
- **并且**保存下载质量偏好
- **并且**保存移除已播放下载的偏好

#### 场景：常规设置
- **当**用户配置常规设置
- **则**系统应保存主题偏好
- **并且**保存语言偏好
- **并且**保存其他用户偏好

### 需求：数据持久化
系统应在本地持久化所有用户数据。

#### 场景：保存播客数据
- **当**用户订阅播客
- **则**系统应将播客元数据保存到本地数据库
- **并且**保存节目列表
- **并且**定期同步更新

#### 场景：保存播放状态
- **当**播放状态发生变化
- **则**系统应保存当前节目
- **并且**保存播放位置
- **并且**保存队列状态

#### 场景：保存用户偏好
- **当**用户更改设置
- **则**系统应持久化所有设置
- **并且**在应用启动时恢复设置

### 需求：错误处理
系统应优雅地处理错误。

#### 场景：网络错误
- **当**网络请求失败
- **则**系统应显示适当的错误消息
- **并且**提供重试选项
- **并且**尽可能保持离线功能

#### 场景：存储错误
- **当**存储操作失败
- **则**系统应显示错误消息
- **并且**记录错误详情
- **并且**尽可能尝试恢复

无 - 这是新功能实现
