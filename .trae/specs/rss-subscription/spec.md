# RSS 订阅功能 Spec

## 为什么

用户需要通过 RSS 订阅源订阅播客，这是播客应用的核心功能。系统需要能够解析 RSS 订阅源、提取播客信息、保存到数据库，并提供友好的订阅体验。

## 变更内容

- 实现 RSS 订阅源解析功能
- 实现播客数据模型和数据库存储
- 实现 RSS 订阅界面和交互逻辑
- 实现订阅验证和错误处理
- 实现播客列表展示
- 实现文件存储策略（音频与图片）
- 实现文件下载和管理功能
- 实现缓存清理机制

## 影响

- 受影响的规格：播客管理、播放功能
- 受影响的代码：Data 层（models、datasources、repositories）、Domain 层（entities、repositories、usecases）、Presentation 层（providers、pages）

## 新增需求

### 需求：RSS 订阅源解析

系统应能够解析 RSS 订阅源并提取播客信息。

#### 场景：解析有效的 RSS 订阅源

- **当**用户输入有效的 RSS 订阅源 URL
- **则**系统应获取 RSS 订阅源内容
- **并且**解析播客元数据（标题、作者、描述、封面图等）
- **并且**解析节目列表
- **并且**返回完整的播客对象

#### 场景：处理无效的 RSS 订阅源

- **当**用户输入无效的 RSS 订阅源 URL
- **则**系统应检测到错误
- **并且**向用户显示友好的错误消息
- **并且**不保存任何数据

#### 场景：处理网络错误

- **当**网络请求失败
- **则**系统应捕获网络异常
- **并且**显示网络错误提示
- **并且**提供重试选项

### 需求：播客数据模型

系统应定义播客的数据模型。

#### 场景：播客模型定义

- **当**定义播客模型
- **则**应包含以下字段：
  - id: String（唯一标识符）
  - title: String（播客标题）
  - subtitle: String（副标题）
  - author: String（作者/发布者）
  - description: String（播客描述）
  - artworkUrl: String（封面图 URL）
  - rssUrl: String（RSS 订阅源 URL）
  - websiteUrl: String（播客官网链接）
  - language: String（语言，如 zh-CN）
  - copyright: String（版权信息）
  - categories: List`String`（分类列表）
  - keywords: String（关键词）
  - isExplicit: bool（是否包含成人内容）
  - ownerName: String（所有者名称）
  - ownerEmail: String（所有者邮箱）
  - lastUpdated: DateTime（最后更新时间）
  - episodeCount: int（节目数量）
  - isSubscribed: bool（是否已订阅）
  - subscribedAt: DateTime（订阅时间）

### 需求：节目数据模型

系统应定义节目的数据模型。

#### 场景：节目模型定义

- **当**定义节目模型
- **则**应包含以下字段：
  - id: String（唯一标识符，使用 guid）
  - podcastId: String（所属播客 ID）
  - title: String（节目标题）
  - description: String（节目描述，可能包含 HTML）
  - link: String（节目链接）
  - guid: String（节目唯一标识符）
  - author: String（节目作者）
  - pubDate: DateTime（发布时间）
  - audioUrl: String（音频文件 URL）
  - audioType: String（音频文件类型，如 audio/mpeg）
  - duration: int（时长，单位：秒）
  - artworkUrl: String（节目封面图 URL）
  - isExplicit: bool（是否包含成人内容）
  - isPlayed: bool（是否已播放）
  - isDownloaded: bool（是否已下载）
  - downloadedPath: String（下载文件路径）
  - downloadProgress: double（下载进度 0.0-1.0）
  - playProgress: int（播放进度，单位：秒）
  - lastPlayedAt: DateTime（最后播放时间）
  - createdAt: DateTime（创建时间）
  - updatedAt: DateTime（更新时间）

### 需求：播客数据库存储

系统应使用 Isar 数据库存储播客数据。

#### 场景：保存播客

- **当**用户订阅播客
- **则**系统应将播客信息保存到 Isar 数据库
- **并且**分配唯一 ID
- **并且**设置订阅状态为 true
- **并且**记录订阅时间

#### 场景：查询已订阅播客

- **当**用户查看播客列表
- **则**系统应从数据库查询所有已订阅播客
- **并且**按最后更新时间排序
- **并且**返回播客列表

#### 场景：取消订阅

- **当**用户取消订阅播客
- **则**系统应从数据库删除该播客
- **并且**级联删除相关节目（可选）

#### 场景：检查重复订阅

- **当**用户尝试订阅已订阅的播客
- **则**系统应检测到重复
- **并且**提示用户该播客已订阅

### 需求：RSS 订阅界面

系统应提供 RSS 订阅界面。

#### 场景：RSS 输入界面

- **当**用户进入订阅页面
- **则**应显示 RSS URL 输入框
- **并且**显示订阅按钮
- **并且**提供输入验证

#### 场景：订阅验证

- **当**用户输入 RSS URL
- **则**系统应验证 URL 格式
- **并且**在用户提交前验证 URL 可访问性
- **并且**显示加载状态

#### 场景：订阅成功反馈

- **当**订阅成功
- **则**应显示成功提示
- **并且**自动跳转到播客详情或列表页面
- **并且**更新播客列表

### 需求：播客列表展示

系统应在资料库页面展示已订阅播客。

#### 场景：显示播客列表

- **当**用户进入资料库页面
- **则**应显示所有已订阅播客
- **并且**显示播客封面、标题、作者
- **并且**显示最新节目信息
- **并且**显示最后更新时间

#### 场景：播客列表交互

- **当**用户点击播客
- **则**应导航到播客详情页面
- **当**用户点击播客更多按钮
- **则**应显示操作菜单（取消订阅、分享等）

### 需求：播客详情页面

系统应提供播客详情页面。

#### 场景：显示播客详情

- **当**用户进入播客详情页面
- **则**应显示播客完整信息
- **并且**显示节目列表
- **并且**提供播放、下载、收藏等操作

#### 场景：节目列表

- **当**查看播客详情
- **则**应显示该播客的所有节目
- **并且**按发布时间倒序排列
- **并且**显示节目标题、描述、时长、发布时间

### 需求：错误处理

系统应优雅地处理 RSS 订阅过程中的错误。

#### 场景：网络超时

- **当**RSS 请求超时
- **则**应显示超时错误
- **并且**提供重试选项

#### 场景：解析错误

- **当**RSS 格式不正确
- **则**应显示解析错误
- **并且**提示用户检查 RSS URL

#### 场景：存储错误

- **当**数据库保存失败
- **则**应显示存储错误
- **并且**记录错误日志

### 需求：文件存储策略

系统应使用合适的文件存储策略来管理音频文件和图片文件，避免将大文件存入数据库。

#### 场景：选择存储目录

- **当**系统初始化文件存储
- **则**应使用 path_provider 包获取各平台的合适目录
- **并且**临时缓存使用 temporaryDirectory（用于未完成的下载或短期缓存）
- **并且**永久存储使用 applicationSupportDirectory（iOS/macOS: Library/Application Support，Android: files 目录，Windows/Linux: AppData 或 .config 目录）

#### 场景：文件命名规范

- **当**保存下载的音频文件
- **则**不应使用原始文件名（可能包含特殊字符或重复）
- **并且**应使用 EpisodeID.mp3 或 Hash(Url).mp3 作为文件名
- **并且**应确保文件名在系统中唯一

#### 场景：数据库存储文件路径

- **当**保存文件路径到数据库
- **则**应只存储相对路径或文件名
- **并且**不应存储绝对路径（因为不同设备路径不同）
- **并且**应用运行时动态拼接完整路径

#### 场景：路径分隔符处理

- **当**拼接文件路径
- **则**应使用 path 包的 path.join() 方法
- **并且**不应使用字符串拼接
- **并且**确保在不同操作系统上正确处理 / 和 \ 分隔符

### 需求：音频文件下载

系统应支持下载播客音频文件到本地存储。

#### 场景：下载音频文件

- **当**用户下载节目音频
- **则**应从 audioUrl 下载音频文件
- **并且**将文件保存到 applicationSupportDirectory
- **并且**使用 EpisodeID.mp3 作为文件名
- **并且**更新数据库中的 isDownloaded 和 downloadedPath 字段
- **并且**显示下载进度

#### 场景：处理下载失败

- **当**下载过程中断或失败
- **则**应保留部分下载的文件在 temporaryDirectory
- **并且**记录下载进度以便断点续传
- **并且**允许用户重新下载

#### 场景：检查文件是否已下载

- **当**用户查看节目列表
- **则**系统应检查本地是否存在音频文件
- **并且**根据数据库中的 downloadedPath 字段验证文件存在性
- **并且**更新 isDownloaded 状态

### 需求：图片缓存

系统应缓存播客封面图和节目封面图以提升性能。

#### 场景：缓存封面图

- **当**加载播客或节目封面图
- **则**应先检查本地缓存
- **并且**如果缓存存在则直接使用
- **并且**如果缓存不存在则从网络下载并缓存
- **并且**使用 Hash(Url) 作为缓存文件名

#### 场景：图片缓存目录

- **当**缓存图片
- **则**应使用 applicationSupportDirectory/images 子目录
- **并且**与音频文件分开存储

### 需求：缓存清理机制

系统应提供缓存清理功能以管理磁盘空间。

#### 场景：手动清理缓存

- **当**用户触发清理缓存
- **则**应提供清理选项（清理所有、清理已播放、保留最近 N 集）
- **并且**根据用户选择删除相应的物理文件
- **并且**更新数据库中的下载状态
- **并且**显示清理结果

#### 场景：自动清理缓存

- **当**磁盘空间不足
- **则**应自动清理最旧的已下载文件
- **并且**优先清理已播放的节目
- **并且**保留用户设定的最近 N 集

#### 场景：取消订阅时清理文件

- **当**用户取消订阅播客
- **则**应删除该播客相关的所有下载文件
- **并且**删除该播客的封面图缓存
- **并且**清理数据库记录

### 需求：文件系统权限

系统应正确处理各平台的文件系统权限。

#### 场景：iOS/macOS 权限

- **当**应用在 iOS/macOS 上运行
- **则**应在应用沙盒内读写文件（无需额外权限）
- **并且**如果需要访问沙盒外文件，应配置 Entitlements

#### 场景：Android 权限

- **当**应用在 Android 上运行
- **则**应使用 files 目录（应用卸载时自动清除）
- **并且**无需额外权限即可读写应用私有目录

#### 场景：Linux 权限

- **当**应用在 Linux 上运行
- **则**应确保应用有权限写入用户目录
- **并且**注意 Snap/Flatpak 的沙盒限制

#### 场景：Windows 权限

- **当**应用在 Windows 上运行
- **则**应使用 AppData 目录
- **并且**避免写入 Program Files 等受保护目录

### 需求：文件管理服务

系统应提供统一的文件管理服务来处理文件操作。

#### 场景：获取存储目录

- **当**应用需要存储文件
- **则**应通过 FileStorageService 获取合适的存储目录
- **并且**返回平台特定的目录路径

#### 场景：文件存在性检查

- **当**需要检查文件是否存在
- **则**应通过 FileStorageService 检查文件存在性
- **并且**返回布尔值

#### 场景：删除文件

- **当**需要删除文件
- **则**应通过 FileStorageService 删除文件
- **并且**处理文件不存在的情况
- **并且**返回删除结果

#### 场景：获取文件大小

- **当**需要获取文件大小
- **则**应通过 FileStorageService 获取文件大小
- **并且**用于计算缓存占用空间
