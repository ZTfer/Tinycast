# RSS 订阅功能 Spec

## 为什么
用户需要通过 RSS 订阅源订阅播客，这是播客应用的核心功能。系统需要能够解析 RSS 订阅源、提取播客信息、保存到数据库，并提供友好的订阅体验。

## 变更内容
- 实现 RSS 订阅源解析功能
- 实现播客数据模型和数据库存储
- 实现 RSS 订阅界面和交互逻辑
- 实现订阅验证和错误处理
- 实现播客列表展示

## 影响
- 受影响的规格：播客管理、播放功能
- 受影响的代码：Data 层（models、datasources、repositories）、Domain 层（entities、repositories、usecases）、Presentation 层（providers、pages）

## 新增需求

### 需求：RSS 订阅源解析
系统应能够解析 RSS 订阅源并提取播客信息。

#### 场景：解析有效的 RSS 订阅源
- **当**用户输入有效的 RSS 订阅源 URL
- **则**系统应获取 RSS 订阅源内容
- **并且**解析播客元数据（标题、作者、描述、封面图等）
- **并且**解析节目列表
- **并且**返回完整的播客对象

#### 场景：处理无效的 RSS 订阅源
- **当**用户输入无效的 RSS 订阅源 URL
- **则**系统应检测到错误
- **并且**向用户显示友好的错误消息
- **并且**不保存任何数据

#### 场景：处理网络错误
- **当**网络请求失败
- **则**系统应捕获网络异常
- **并且**显示网络错误提示
- **并且**提供重试选项

### 需求：播客数据模型
系统应定义播客的数据模型。

#### 场景：播客模型定义
- **当**定义播客模型
- **则**应包含以下字段：
  - id: String（唯一标识符）
  - title: String（播客标题）
  - subtitle: String（副标题）
  - author: String（作者/发布者）
  - description: String（播客描述）
  - artworkUrl: String（封面图 URL）
  - rssUrl: String（RSS 订阅源 URL）
  - websiteUrl: String（播客官网链接）
  - language: String（语言，如 zh-CN）
  - copyright: String（版权信息）
  - categories: List<String>（分类列表）
  - keywords: String（关键词）
  - isExplicit: bool（是否包含成人内容）
  - ownerName: String（所有者名称）
  - ownerEmail: String（所有者邮箱）
  - lastUpdated: DateTime（最后更新时间）
  - episodeCount: int（节目数量）
  - isSubscribed: bool（是否已订阅）
  - subscribedAt: DateTime（订阅时间）

### 需求：节目数据模型
系统应定义节目的数据模型。

#### 场景：节目模型定义
- **当**定义节目模型
- **则**应包含以下字段：
  - id: String（唯一标识符，使用 guid）
  - podcastId: String（所属播客 ID）
  - title: String（节目标题）
  - description: String（节目描述，可能包含 HTML）
  - link: String（节目链接）
  - guid: String（节目唯一标识符）
  - author: String（节目作者）
  - pubDate: DateTime（发布时间）
  - audioUrl: String（音频文件 URL）
  - audioType: String（音频文件类型，如 audio/mpeg）
  - duration: int（时长，单位：秒）
  - artworkUrl: String（节目封面图 URL）
  - isExplicit: bool（是否包含成人内容）
  - isPlayed: bool（是否已播放）
  - isDownloaded: bool（是否已下载）
  - downloadedPath: String（下载文件路径）
  - downloadProgress: double（下载进度 0.0-1.0）
  - playProgress: int（播放进度，单位：秒）
  - lastPlayedAt: DateTime（最后播放时间）
  - createdAt: DateTime（创建时间）
  - updatedAt: DateTime（更新时间）

### 需求：播客数据库存储
系统应使用 Isar 数据库存储播客数据。

#### 场景：保存播客
- **当**用户订阅播客
- **则**系统应将播客信息保存到 Isar 数据库
- **并且**分配唯一 ID
- **并且**设置订阅状态为 true
- **并且**记录订阅时间

#### 场景：查询已订阅播客
- **当**用户查看播客列表
- **则**系统应从数据库查询所有已订阅播客
- **并且**按最后更新时间排序
- **并且**返回播客列表

#### 场景：取消订阅
- **当**用户取消订阅播客
- **则**系统应从数据库删除该播客
- **并且**级联删除相关节目（可选）

#### 场景：检查重复订阅
- **当**用户尝试订阅已订阅的播客
- **则**系统应检测到重复
- **并且**提示用户该播客已订阅

### 需求：RSS 订阅界面
系统应提供 RSS 订阅界面。

#### 场景：RSS 输入界面
- **当**用户进入订阅页面
- **则**应显示 RSS URL 输入框
- **并且**显示订阅按钮
- **并且**提供输入验证

#### 场景：订阅验证
- **当**用户输入 RSS URL
- **则**系统应验证 URL 格式
- **并且**在用户提交前验证 URL 可访问性
- **并且**显示加载状态

#### 场景：订阅成功反馈
- **当**订阅成功
- **则**应显示成功提示
- **并且**自动跳转到播客详情或列表页面
- **并且**更新播客列表

### 需求：播客列表展示
系统应在资料库页面展示已订阅播客。

#### 场景：显示播客列表
- **当**用户进入资料库页面
- **则**应显示所有已订阅播客
- **并且**显示播客封面、标题、作者
- **并且**显示最新节目信息
- **并且**显示最后更新时间

#### 场景：播客列表交互
- **当**用户点击播客
- **则**应导航到播客详情页面
- **当**用户长按播客
- **则**应显示操作菜单（取消订阅、分享等）

### 需求：播客详情页面
系统应提供播客详情页面。

#### 场景：显示播客详情
- **当**用户进入播客详情页面
- **则**应显示播客完整信息
- **并且**显示节目列表
- **并且**提供播放、下载、收藏等操作

#### 场景：节目列表
- **当**查看播客详情
- **则**应显示该播客的所有节目
- **并且**按发布时间倒序排列
- **并且**显示节目标题、描述、时长、发布时间

### 需求：错误处理
系统应优雅地处理 RSS 订阅过程中的错误。

#### 场景：网络超时
- **当**RSS 请求超时
- **则**应显示超时错误
- **并且**提供重试选项

#### 场景：解析错误
- **当**RSS 格式不正确
- **则**应显示解析错误
- **并且**提示用户检查 RSS URL

#### 场景：存储错误
- **当**数据库保存失败
- **则**应显示存储错误
- **并且**记录错误日志
