# Podcast 刷新机制测试指南

## 自动化测试

运行单元测试：
```bash
flutter test test/data/services/feed_refresh_service_test.dart
```

运行所有测试：
```bash
flutter test
```

---

## 手动测试场景

### 1. 基本刷新功能测试

**前提条件：**
- 确保已订阅至少一个播客

**测试步骤：**
1. 打开应用，进入 Library 页面
2. 下拉刷新页面
3. 观察是否有 Toast 提示刷新结果（如"发现 X 集新内容"）

**预期结果：**
- 显示加载指示器
- 刷新完成后显示新内容数量
- 播客列表更新

---

### 2. 网络状态智能判断测试

**测试 WiFi 网络：**
1. 连接 WiFi
2. 下拉刷新
3. 预期：正常刷新

**测试蜂窝网络（如果设备支持）：**
1. 断开 WiFi，使用蜂窝网络
2. 打开设置 → 刷新设置 → 关闭"仅 WiFi 刷新"
3. 回到 Library 下拉刷新
4. 预期：正常刷新
5. 打开"仅 WiFi 刷新"
6. 预期：静默跳过或提示无法刷新

**测试无网络：**
1. 开启飞行模式
2. 下拉刷新
3. 预期：静默跳过，不显示错误

---

### 3. 防抖动机制测试

**测试步骤：**
1. 下拉刷新一次
2. 等待几秒
3. 再次下拉刷新

**预期结果：**
- 第一次刷新正常执行
- 第二次刷新在 5 分钟内会被跳过（冷却机制）
- 日志中会显示"播客 X 刷新冷却中，跳过"

---

### 4. 降级策略测试

**前提条件：**
- 使用一个无效的 RSS URL（如 `https://example.com/invalid.xml`）

**测试步骤：**
1. 手动触发该播客刷新（可在播客详情页）
2. 重复 3 次
3. 观察 Library 列表中的播客项

**预期结果：**
- 连续失败 3 次后，播客旁边显示橙色警告图标
- 后续自动刷新会跳过该播客（退化模式）
- 日志中显示"播客 X 刷新失败次数达 3，进入退化模式"

---

### 5. 刷新频率设置测试

**测试步骤：**
1. 打开设置 → 刷新设置
2. 修改"刷新频率"为不同选项
3. 切换"仅 WiFi 刷新"开关
4. 切换"刷新通知"开关
5. 切换"后台刷新"开关

**预期结果：**
- 所有开关正常工作
- 设置持久化（关闭应用后重新打开仍然保持）
- 日志记录设置变更

---

### 6. 增量更新测试

**测试步骤：**
1. 订阅一个更新频率较低的播客
2. 首次刷新 - 记录下载的剧集数量
3. 等待播客发布新内容（或等待下次自动刷新）
4. 再次刷新 - 观察新增剧集数量

**预期结果：**
- 第一次刷新下载所有现有剧集
- 后续刷新仅下载新增剧集
- 不会重复下载已有剧集

---

### 7. 应用生命周期测试

**测试步骤：**
1. 设置刷新频率为"每 1 小时"
2. 将应用切换到后台（Cmd+H）
3. 等待超过 1 小时
4. 检查是否执行了后台刷新（查看日志或新剧集）
5. 关闭"后台刷新"开关
6. 重复步骤 2-4

**预期结果：**
- 开启后台刷新时，应用后台期间也会刷新
- 关闭后台刷新时，应用后台期间不会刷新
- 应用回到前台时调度器自动恢复

---

## 调试技巧

### 查看日志

在终端中运行应用查看详细日志：
```bash
flutter run
```

日志会显示：
- 刷新开始和结束
- 新增剧集数量
- 失败原因
- 冷却和降级状态

### 缩短测试时间

为了方便测试，可以临时修改 `FeedRefreshService` 中的冷却时间：
```dart
// 在 feed_refresh_service.dart 第 52 行
static const _cooldownDuration = Duration(seconds: 10); // 改为 10 秒
```

### 验证数据库状态

可以使用 Isar Inspector 查看数据库状态：
```bash
# 在调试模式下运行应用
flutter run --dart-define=ISAR_INSPECTOR=true
```

然后打开浏览器访问 `http://localhost:8080` 查看 `lastFetchedAt` 和 `refreshFailedCount` 字段。
